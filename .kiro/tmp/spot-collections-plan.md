# Plan: Persönliche Spot-Sammlungen (Personal Spot Collections)

## Feature summary
Users create named personal collections ("Schöne Orte am Wasser", "Wochenendtrips") and save spots into them. Requires: (a) make EXISTING map spot pins tappable to open a detail surface, (b) a collection-picker to assign/unassign a spot, (c) a third "Sammlungen" tab in the profile segmented control to list/organize/create/rename/delete collections.

## Whole-feature risk: MEDIUM. No SQLDelight schema bump (in-memory seam) → no migration-crash risk. Map-pin tappability is the one real technical unknown.

## KEY DECISIONS
1. DB: `collections` (id, owner_id FK auth.users ON DELETE CASCADE, name, created_at, updated_at + set_updated_at trigger) + `collection_spots` join (collection_id FK collections ON DELETE CASCADE, spot_id FK spots ON DELETE CASCADE, created_at, composite PK (collection_id, spot_id)). Owner-scoped RLS (personal collections): collections SELECT/INSERT/UPDATE/DELETE gated owner_id = auth.uid(); join table gated via EXISTS against parent collection ownership. Public/shared collections DEFERRED.
2. NO durable SQLDelight cache: in-memory seam like Follow/Profile (no .sqm, schema stays v4, no migration test). Collections are small + cheap to refetch.
3. Shared seam mirrors FollowRepository exactly: CollectionModels.kt, CollectionRepository.kt (+ Collections provider), SupabaseCollectionRepository.kt (CollectionRemoteSource + @Serializable internal DTOs). Pure reads, explicit Mutex-coalesced refreshes on Dispatchers.Default, optimistic writes with NO durable queue, best-effort (never throws), onChanged. Client-side join for spotsIn (proven Postgrest API only: select{filter{eq}}.decodeList, insert, delete{filter}, update; no embed, no Count.EXACT, no in/isin). Counts via .decodeList().size.
4. Flat bridge: IosSpotCollection(id, name, spotCount, createdAtLabel) + in-memory holders; all callbacks on Main via onMain; no suspend/supabase/nullable/Long crosses.
5. Map spot-tap: Mapbox v11 data-driven `CircleAnnotation(...).onTapGesture { }` inside the existing CircleAnnotationGroup(spots){ spot in } — the spot is in closure scope so it resolves which UISpot was tapped → onSpotTap(UISpot). Least-invasive; keeps POI/empty-map TapInteraction precedence. Fallback if the symbol doesn't compile on 11.19.0: PointAnnotation/PointAnnotationGroup .onTapGesture, or a TapInteraction(featureset:) against the group's layer. Builder confirms the symbol compiles before wiring; if neither compiles, STOP after 3 attempts and report (do not reshape the boundary).
6. Spot detail surface: NEW lean MapSpotSheetView(spot: UISpot) with one "In Sammlung speichern" action opening the collection picker — do NOT generalize the post-bound SpotSheetView(UIPost).
7. Profile third tab + dedicated CollectionsStore (@Observable, mirrors FollowStore). ProfileTab gains .collections; tapping a collection pushes CollectionDetailView inside the Profile tab's NavigationStack; a "+" creates one.
8. i18n keys (DE+EN, typed): collectionsTabTitle, newCollection, collectionNamePlaceholder, createCollection, saveToCollection, addToCollection, removeFromCollection, renameCollection, deleteCollection, emptyCollections, emptyCollectionSpots, + plural function collectionSpotCount(count). Collection names users type are dynamic, NOT translated.
