## Workstream A — BUGFIX (LOW-MEDIUM): 400 "invalid input syntax for type uuid: spot-bonanza" saving a spot to a collection
Root cause (confirmed): SampleData.kt seeds 6 spots with NON-UUID ids (spot-prater/bonanza/volkspark/klunker/tempelhof/companion); CachingSpotRepository seeds the cache from them pre-login/offline; MapSpotSheetView→CollectionPickerSheetView→CollectionRepository.addSpot→SupabaseCollectionRepository.addSpot sends spot_id into the uuid column collection_spots.spot_id → 22P02. Deeper: seed spots aren't DB rows, so even a valid UUID fails the FK to public.spots.
Fix = option (c): (a) a shared UUID-shape guard in CollectionRepository.addSpot that rejects a non-uuid spotId as a no-op reporting false (NO remote call), unit-tested; (b) give the SampleData seed spots real constant lowercase UUID ids (cleanup; insufficient alone — they still aren't DB rows); (c) reflect non-addable spots in the picker UI (the collection picker shows a short "this spot can't be saved yet" note / disables toggles when the spot id isn't a uuid). Flat boundary intact. Live INSERT success stays BLOCKED-until-session; the guard+tests are provable now.
