# Supabase-backed shared feed layer (Phase B)

Phase B swaps the SwiftUI feed's data source from in-memory `SampleData` to an offline-first shared stack: a Postgrest remote over the `post_feed` view + `post_comments`, a SQLDelight cache with a comment pending-queue, a read-only `FeedRepository` and a read/write `CommentRepository`, a hand-rolled `RelativeTime` formatter/ISO-parser, and three new flat `FeedBridge` hooks (`loadFeed`/`observeFeed`/`addComment`). The design mirrors the already-shipped spots offline seam almost one-for-one, which keeps the shape familiar and the risk contained. `IosPost`/`IosComment` keep their exact flat fields, so no Swift view changed — only `iOSApp.swift` was touched, and only to rename the Supabase key from `anon` to `publishable`.

Watch for: the `post_feed` view uses INNER joins to `profiles` and `spots` (confirmed) — a post whose author profile or spot row is missing silently drops from the feed; acceptable for Phase B but worth knowing. The comment author name resolves via a PostgREST `profiles(name)` embed with an honest empty-string fallback (confirmed), so no wrong-user name can appear. The `RelativeTime` ISO parser is hand-rolled; I hand-verified its epochs and offset math against Python and they are correct (confirmed).

**Verdict**: APPROVED

## High-level view

The flat FeedBridge boundary holds. Every Swift-facing signature carries only String/Int/Bool/Double and no-arg or `(String,String,()->Unit)` closures; `Long`, `suspend`, `Flow`, the supabase/SQLDelight types, and the internal `FeedPost`/`FeedComment`/DTO shapes never appear in a signature (only in docstrings). The post's `createdAtEpoch: Long` is formatted to a `dateLabel`/`timeLabel` String shared-side via `RelativeTime.format` before it crosses, so no Long leaks. All three new hooks deliver their completions on `Dispatchers.Main` via `authScope`.

The offline-first behavior is a faithful mirror of the spots seam and is crash-safe when unconfigured/offline/unauthenticated. Reads are cache-first and synchronous; a background coroutine refreshes only when `isAvailable() && isAuthenticated()`, and every remote call is wrapped so a throw keeps serving the cache. The cache seeds from `SampleData` when empty so the feed is never blank pre-login. Comment writes are optimistic + enqueued; a failed push leaves the item queued, and the flush stops on first failure to preserve order.

The `RelativeTime` parser is dependency-free and correct for the documented Postgres `timestamptz` shapes (Z, `+hh:mm`/`-hh:mm`/`+hh` offsets, fractional seconds, space separator). Howard Hinnant's `days_from_civil` is used for the date→epoch conversion; I hand-checked the UTC-Z and fractional+offset test epochs against Python and both match. Unparseable input returns `0L` rather than throwing. The `format` buckets and de/en labels (including the Tag/Tagen singular-plural and future-clamp) match the tests.

The SQLDelight additions (`cachedPosts`, `cachedComments`, `pendingCommentInserts` + queries) are purely additive — the `cachedSpots`/`pendingSpotInserts` tables and queries are untouched. Query names/params line up with `LocalFeedCache`, `created_at` is stored as epoch INTEGER, and the orderings (posts DESC, comments ASC, queue ASC) are enforced in SQL and verified by the real in-memory JDBC round-trip test.

The comment author-name approach is honest: `CommentDto.profiles` is nullable and the mapping is `dto.profiles?.name.orEmpty()`, so a missing embed yields an empty name, never a fabricated or wrong one. Scope is respected: posts are read-only, no voting writes, `my_vote` is the view's `'NONE'` placeholder, `score` is `0`, no new i18n keys (RelativeTime is self-contained, StringsTest unchanged at 16), and the real Supabase round-trip is correctly left BLOCKED-until-keys rather than faked.

## Flat boundary integrity

`posts()` returns `List<IosPost>` and `comments(postId)` returns `List<IosComment>` with their field sets unchanged from the SampleData era, so the existing SwiftUI feed and comments sheet compile and render without edits. The three new hooks are `loadFeed(() -> Unit)`, `observeFeed(() -> Unit)`, and `addComment(String, String, () -> Unit)` — all flat, all scheduling their completion on `authScope.launch { ... }` where `authScope = CoroutineScope(Dispatchers.Main)`, so Swift `@Observable` mutations in the callbacks are main-thread safe.

A grep of the bridge for `Long|suspend|Flow|PostFeedDto|CommentDto|FeedPost|FeedComment` returns only docstring matches and the internal `AuthRepository.authStateFlow()` collection inside `observeAuth` (the Flow is consumed inside the shared scope; only `(Bool, String)` reaches the listener). No internal type appears in any Swift-facing signature.

The Long question matters most here because `FeedPost`/`FeedComment` both carry `createdAtEpoch: Long`. That epoch stays inside the shared module: `posts()` and `comments()` call `RelativeTime.format(post.createdAtEpoch, now, currentLanguageCode)` and cross only the resulting `String` as `dateLabel`/`timeLabel`. The Long never reaches the ObjC header.

## RelativeTime: hand-rolled parser and formatter

This is the one novel, correctness-sensitive piece. The parser avoids a datetime dependency by splitting the ISO string manually: separator on `T` or space, offset extracted by locating `Z` or the last `+`/`-` in the time part, fractional seconds truncated to three digits, and the date converted with Hinnant's `days_from_civil`. The wall-clock millis are then converted to UTC via `utcMillis - offsetMillis`.

I traced the offset sign convention on a case the tests do not cover, `...T12:30:00.123-05:00`: sign `-1`, `offsetMillis = -(5h)`, and `utcMillis - (-(5h)) = utcMillis + 5h`, which correctly turns 12:30 at UTC-5 into 17:30 UTC. The positive-offset test (`14:30:00.123+02:00 == 12:30:00.123 UTC`) exercises the mirror case and passes. I confirmed the two anchor epochs against Python: `2024-03-15T12:30:00Z → 1710505800000` matches, and the fractional variant adds exactly `123` millis as asserted. Unparseable input is caught and returns `0L`, so a bad row sorts oldest and never crashes.

One narrow edge: a string with no `T` or space (`sepIndex < 0`) returns `0L` — a bare date like `"2024-03-15"` silently becomes the Unix epoch. Postgres `timestamptz` always includes a time, so this cannot fire for the documented inputs, but it is a latent surprise if the parser is ever reused for date-only values.

`format` is straightforward bucketed arithmetic with a `coerceAtLeast(0L)` future-clamp. The de/en labels, the `Tag`/`Tagen` singular-plural split, and the unknown-language→German fallback all match the asserted strings.

## Offline-first repositories

`FeedRepository.getPosts()` returns the cache synchronously and launches `refreshFromRemote()`, which no-ops unless `remote.isAvailable() && isAuthenticated()` and wraps the fetch→replaceAll→onChanged in a try/catch that swallows transient failures. The constructor seeds from `FeedMapping.defaultPostSeed` when the cache is empty, so the feed is populated pre-login and offline. The fake-remote tests confirm the unauthenticated path makes zero remote calls and the online path replaces the cache and fires `onChanged`.

`CommentRepository` adds the write path. `addComment` trims and ignores blank text, writes an optimistic `FeedComment` (author = current user's display/email, `createdAtEpoch = now`), enqueues a `PendingCommentInsert` tagged with `authorIdProvider()` from the session, fires `onChanged`, then launches `flushPending()`. The refresh path flushes the queue *before* fetching, so a just-pushed optimistic comment is present in the fetched replace-all rather than clobbered. `flushPendingLocked` dequeues on success and breaks on the first failure, preserving oldest-first order for the next retry. The failed-insert test confirms a thrown insert leaves the item queued with the optimistic copy intact and no crash.

The `Feed` provider shares a single cache instance between the post and comment repositories and falls back to `InMemoryFeedCache` if the SQLDelight driver cannot be built, so even a driver failure degrades to the SampleData seed rather than a crash.

## Comment author name — honest fallback

`post_comments` stores only `author_id`, so the display name is resolved by embedding `profiles(name)` in the select via `Columns.raw("id, post_id, author_id, text, created_at, profiles(name)")`. `CommentDto.profiles` is nullable and the map is `dto.profiles?.name.orEmpty()`. A missing or unresolvable profile row therefore yields an empty author name — never a stale or wrong user's name. The embed is a one-to-one relationship keyed on `author_id`, so there is no path for another user's name to attach to a comment.

## SQLDelight schema

The three new tables and their queries are appended below the existing spots DDL with an explicit "ADDITIVE" banner; the `cachedSpots`/`pendingSpotInserts` definitions and queries are byte-for-byte unchanged. `created_at_epoch` is `INTEGER`, booleans are `INTEGER` 0/1, and `my_vote` defaults to `'NONE'`. Orderings live in SQL — `selectAllCachedPosts` is `DESC`, `selectCachedComments` is `ASC`, both pending queues are `enqueued_at ASC`. The query names and bound parameters line up exactly with the `LocalFeedCache` call sites. `LocalFeedCacheDbTest` exercises all of this over a real in-memory `JdbcSqliteDriver`, including an offline-add-then-online-flush end-to-end through `CommentRepository`, and asserts the DESC/ASC orderings and the dequeue.
